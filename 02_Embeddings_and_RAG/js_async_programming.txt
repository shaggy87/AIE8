JavaScript Asynchronous Programming Guide

Introduction to Asynchronous JavaScript
JavaScript is single-threaded, meaning it can only execute one piece of code at a time. However, it can handle asynchronous operations through various mechanisms that allow non-blocking execution.

The Event Loop
The event loop is the core mechanism that enables asynchronous behavior in JavaScript. It continuously checks the call stack and processes tasks from the task queue.

Call Stack: Where function calls are stored
Web APIs: Browser-provided APIs (setTimeout, fetch, DOM events)
Task Queue: Where completed async operations wait
Event Loop: Moves tasks from queue to call stack when stack is empty

Callbacks
The traditional way to handle asynchronous operations in JavaScript.

Example:
function fetchData(callback) {
    setTimeout(() => {
        const data = "Hello from server";
        callback(data);
    }, 1000);
}

fetchData((result) => {
    console.log(result); // "Hello from server"
});

Callback Hell
When callbacks are nested multiple times, code becomes difficult to read and maintain:

getData((a) => {
    getMoreData(a, (b) => {
        getEvenMoreData(b, (c) => {
            getFinalData(c, (d) => {
                console.log(d);
            });
        });
    });
});

Promises
Promises provide a cleaner alternative to callbacks for handling asynchronous operations.

Creating a Promise:
const myPromise = new Promise((resolve, reject) => {
    setTimeout(() => {
        const success = true;
        if (success) {
            resolve("Operation successful!");
        } else {
            reject("Operation failed!");
        }
    }, 1000);
});

Using Promises:
myPromise
    .then((result) => {
        console.log(result);
    })
    .catch((error) => {
        console.error(error);
    });

Promise Chaining
Promises can be chained to handle sequential asynchronous operations:

fetch('/api/user')
    .then(response => response.json())
    .then(user => fetch(`/api/posts/${user.id}`))
    .then(response => response.json())
    .then(posts => console.log(posts))
    .catch(error => console.error(error));

Promise.all()
Execute multiple promises concurrently:

const promise1 = fetch('/api/data1');
const promise2 = fetch('/api/data2');
const promise3 = fetch('/api/data3');

Promise.all([promise1, promise2, promise3])
    .then(responses => {
        // All promises resolved
        return Promise.all(responses.map(r => r.json()));
    })
    .then(data => {
        console.log('All data:', data);
    })
    .catch(error => {
        console.error('One or more promises failed:', error);
    });

Promise.race()
Returns the first promise to settle (resolve or reject):

const timeout = new Promise((_, reject) =>
    setTimeout(() => reject(new Error('Timeout')), 5000)
);

const fetchData = fetch('/api/slow-endpoint');

Promise.race([fetchData, timeout])
    .then(response => response.json())
    .then(data => console.log(data))
    .catch(error => console.error(error));

Async/Await
ES2017 introduced async/await, which provides a more synchronous-looking way to write asynchronous code.

Basic Async Function:
async function fetchUserData(userId) {
    try {
        const response = await fetch(`/api/users/${userId}`);
        const user = await response.json();
        return user;
    } catch (error) {
        console.error('Error fetching user:', error);
        throw error;
    }
}

Using Async Functions:
async function main() {
    try {
        const user = await fetchUserData(123);
        console.log(user);
    } catch (error) {
        console.error('Failed to get user data');
    }
}

main();

Error Handling with Async/Await
Always wrap async operations in try-catch blocks:

async function complexOperation() {
    try {
        const step1 = await firstAsyncOperation();
        const step2 = await secondAsyncOperation(step1);
        const step3 = await thirdAsyncOperation(step2);
        return step3;
    } catch (error) {
        console.error('Operation failed at:', error.message);
        // Handle error appropriately
        return null;
    }
}

Parallel vs Sequential Execution
Sequential (one after another):
async function sequential() {
    const result1 = await operation1(); // Wait for this
    const result2 = await operation2(); // Then wait for this
    return [result1, result2];
}

Parallel (simultaneously):
async function parallel() {
    const [result1, result2] = await Promise.all([
        operation1(), // Start both
        operation2()  // at the same time
    ]);
    return [result1, result2];
}

Common Async Patterns

1. Retry Pattern:
async function retryOperation(operation, maxRetries = 3) {
    for (let i = 0; i < maxRetries; i++) {
        try {
            return await operation();
        } catch (error) {
            if (i === maxRetries - 1) throw error;
            await new Promise(resolve => setTimeout(resolve, 1000 * i));
        }
    }
}

2. Timeout Pattern:
function withTimeout(promise, timeoutMs) {
    const timeout = new Promise((_, reject) =>
        setTimeout(() => reject(new Error('Timeout')), timeoutMs)
    );
    return Promise.race([promise, timeout]);
}

3. Debounce Pattern:
function debounce(fn, delay) {
    let timeoutId;
    return (...args) => {
        clearTimeout(timeoutId);
        timeoutId = setTimeout(() => fn.apply(this, args), delay);
    };
}

Working with APIs
Modern API calls using fetch with async/await:

async function apiCall(endpoint, options = {}) {
    try {
        const response = await fetch(endpoint, {
            method: 'GET',
            headers: {
                'Content-Type': 'application/json',
                ...options.headers
            },
            ...options
        });

        if (!response.ok) {
            throw new Error(`HTTP error! status: ${response.status}`);
        }

        const data = await response.json();
        return data;
    } catch (error) {
        console.error('API call failed:', error);
        throw error;
    }
}

Best Practices
1. Always handle errors in async operations
2. Use async/await for better readability
3. Prefer Promise.all() for concurrent operations
4. Avoid mixing callbacks with promises
5. Use proper error boundaries
6. Consider timeout handling for long operations
7. Be mindful of memory leaks with pending promises

Performance Considerations
- Don't await in loops unless you need sequential execution
- Use Promise.all() for parallel operations
- Implement proper error handling to prevent hanging promises
- Consider using Web Workers for CPU-intensive tasks
- Cache async results when appropriate

Testing Async Code
Use testing frameworks that support async operations:

// Jest example
test('async function test', async () => {
    const result = await myAsyncFunction();
    expect(result).toBe('expected value');
});

// Mocking async functions
jest.mock('./api');
const mockApi = require('./api');
mockApi.fetchData.mockResolvedValue('mocked data');

Common Pitfalls
1. Forgetting to await async calls
2. Not handling promise rejections
3. Creating unnecessary promise chains
4. Blocking event loop with synchronous operations
5. Not cleaning up resources in async functions
